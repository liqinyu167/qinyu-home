# curiosity.best 持续优化清单

> 目标：把 curiosity.best 从“收录很多站点的个人工具箱”，逐步变成一个让访客快速理解、愿意探索、信任推荐并持续回访的中文导航与发现产品。
>
> 状态：规划草案，尚未实施。每一项都必须经过“小步修改 → 桌面/移动验证 → 指标复核 → 独立审查 → 提交发布”。
>
> 基线日期：2026-08-13

---

## 一、产品北极星

### 一句话定位

**白刀持续亲自筛选、验证并建立关联的 AI 工具、审美作品与灵感来源导航。**

它不只是链接目录，而是帮助访客完成三件事：

1. **有目标时快速找到合适工具**；
2. **没目标时发现值得探索的站点**；
3. **比较模型和同类产品后做出选择**。

### 核心用户

- 想快速找到可用 AI 工具的中文用户；
- 想了解近期新产品但不愿自己筛选噪音的人；
- 创作者、设计师和开发者；
- 需要模型能力、价格和入口对照的人。

### 设计原则

1. **搜索和发现优先**：进入后 10 秒内找到下一步。
2. **策展优先于数量**：解释“为什么值得点”，不只显示“收录了多少”。
3. **可信优先于热闹**：展示验证时间、适用人群和限制，不伪造热门度。
4. **效率优先于装饰**：保留品牌气质，但不让大图、动画和空功能阻挡访问。
5. **移动端优先**：手机上一只手完成搜索、筛选、打开和收藏。
6. **数据驱动但保护隐私**：只记录匿名行为事件，不采集敏感输入或完整 IP。

### 不做什么

- 不做“大厂官网大全”；
- 不用站点总数冒充内容质量；
- 不添加强制登录、首屏广告或阻塞式动画；
- 不制造虚假的浏览量、热度和编辑评分；
- 不一次重写整个单页应用；
- 不为追求“高级感”牺牲信息可读性和打开效率。

### 竞品实测启示

| 产品 | 线上实测到的核心表达 | 值得借鉴 | 不照搬 |
|---|---|---|---|
| Futurepedia | 明确承诺“一站掌握 AI”，突出每日更新和独立平台 | 清晰定位、更新频率、信任说明 | 课程和会员转化结构 |
| Muzli | “专家策展、每天新鲜、持续 12 年” | 编辑人格、新鲜度、长期维护证明 | 面向设计师的单一内容流 |
| Godly | 极简分类，高质量视觉样本优先 | 低负担浏览、视觉质量门槛 | 只展示图片、弱化中文说明 |
| TAAFT / Product Hunt | 本次服务器访问被 Cloudflare 阻断 | 不将无法验证页面作为设计证据 | 不根据阻断页推断产品现状 |

共同结论：优秀导航站的吸引力来自**清晰定位、编辑策展、内容新鲜度和可信维护**，不是继续增加链接数量。

## 二、当前基线

### 产品与内容

- 导航站点：**217**
  - 工具：135
  - 审美：41
  - 灵感：41
- 已有能力：全文搜索、标签筛选、分类树、随机发现、本地收藏、模型排行榜、站点关系。
- 所有站点有描述；215 个站点有标签。
- 当前数据没有 `added_at`、`verified_at`、`featured`、`editor_pick` 等策展字段。

### 线上体验

- 桌面和移动端均无横向溢出，浏览器控制台无报错。
- 首次实测传输约 0.59–0.63 MB，DOMContentLoaded 约 0.23–0.75 秒。
- 桌面进入工具箱后首屏直接面对 135 个工具卡片；移动端为单列长列表。
- 首屏主视觉辨识度高，但人物图的视觉权重超过“导航与发现”的产品定位。
- 工具箱更像数据库目录，缺少“今日精选、最近新增、为什么推荐”等策展入口。

### 流量与度量

- 现有 Nginx 日志不能精确识别真人，也无法看到搜索、分类切换、站点点击和回访。
- 2026-08-13 严格请求链复核：未确认到外部真人浏览会话，大部分主页请求是扫描器或自动化流量。
- 当前没有前端行为分析埋点。

### 已发现的可信度问题

- 侧栏“笔记、模板、素材”是禁用占位项。
- “投稿入口”仍指向 `submit@example.com`。
- “恐龙游戏”与导航主任务无关。
- `/manifest.webmanifest` 当前返回 HTML，而不是有效 Web App Manifest。
- 搜索无结果时仍显示通用“AI Agent 持续维护”文案，没有纠错、推荐或反馈入口。

## 三、核心指标

原始请求数、唯一 IP 和爬虫请求不得作为产品增长指标。

| 指标 | 定义 | 第一阶段目标 |
|---|---|---|
| 可确认真人会话 | 加载应用并触发至少一个真实交互事件的匿名会话 | 建立可信基线，不预设虚假目标 |
| 首屏进入率 | 点击“进入探索”或直接使用首屏搜索的会话 / 首屏会话 | ≥ 45% |
| 站点外链点击率 | 至少打开一个站点的会话 / 真人会话 | ≥ 35% |
| 首次有效点击时间 | 页面打开到第一次站点外链点击的中位时间 | ≤ 45 秒 |
| 搜索使用率 | 使用搜索的会话 / 真人会话 | ≥ 20% |
| 搜索成功率 | 搜索后打开结果站点的会话 / 搜索会话 | ≥ 55% |
| 搜索零结果率 | 返回零结果的搜索次数 / 总搜索次数 | ≤ 8% |
| 随机发现转化率 | 使用随机发现后打开站点的会话 / 随机会话 | ≥ 25% |
| 收藏率 | 至少收藏一个站点的会话 / 真人会话 | ≥ 8% |
| 7 日回访率 | 7 天内再次访问的匿名访客 / 首访匿名访客 | 建基线后连续两轮提升 |
| 外链有效率 | 最近自动验证为可访问的活跃站点 / 全部站点 | ≥ 98%（分地区说明） |
| 移动端可用性 | 核心流程移动端自动化测试通过率 | 100% |
| Web 性能 | LCP / INP / CLS（移动端 P75） | ≤2.5s / ≤200ms / ≤0.1 |

> 上述增长目标只有在累计至少 100 个可确认真人会话后才用于判断成败；样本不足时只报告事实，不做夸大结论。

## 四、P0：先让人看懂、信任并可度量

> 目标：建立真实数据基线，减少第一印象中的干扰，打通“理解 → 搜索/探索 → 打开站点”。

### P0-1 建立隐私友好的真人行为基线

- **问题**：Nginx 请求量大量混入扫描器，无法判断真实用户行为。
- **动作**：接入轻量自托管分析或自有匿名事件接口；记录 `page_view`、`enter_toolbox`、`search`、`filter`、`random_discovery`、`site_open`、`favorite`、`model_view`。为匿名会话生成短期 ID，不记录搜索原文、完整 IP、Cookie 内容和设备指纹。
- **预期收益**：以后每次优化都能判断是否真的改善，而不是凭感觉。
- **验收指标**：事件可在本地和生产环境验证；机器人请求不自动计入真人会话；拥有按天、设备和来源汇总的漏斗；隐私说明同步更新。
- **风险/依赖**：需决定采用 Umami/Plausible 或自有最小事件接口；2GB 服务器优先选择低资源方案。
- **状态**：`[ ]`

### P0-2 重写首屏价值表达

- **问题**：“你需要的只有好奇心”有品牌感，但首次访客无法立即知道网站具体提供什么。
- **动作**：保留主标语，增加一句清晰副标题，例如“白刀亲自筛选的 AI 工具、模型排行与灵感导航”；补充三项可验证价值：“持续验证”“中文说明”“工具关系”；CTA 改为“开始探索 217 个精选站点”。
- **预期收益**：5 秒内理解定位，提高进入率。
- **验收指标**：5 人可用性测试中 4 人能准确复述用途；首屏进入率达到 45%；移动端首屏无需滚动即可看到定位与 CTA。
- **风险/依赖**：文案要随站点数量自动更新，不能写死。
- **状态**：`[ ]`

### P0-3 降低主视觉对产品信息的压制

- **问题**：二次元人物图构图突出，但容易让新访客误认为壁纸或个人作品网站。
- **动作**：不删除品牌主视觉；降低图像占比和对比度，把搜索/定位放到视觉中心；桌面保留左右构图，手机改为文字与搜索优先、图片作为下方氛围图。后续测试一版更偏“发现宇宙/索引卡片”的品牌视觉。
- **预期收益**：保留辨识度，同时减少产品误判。
- **验收指标**：移动端首屏出现清晰搜索入口；5 秒定位测试通过率 ≥80%；不增加首屏资源体积。
- **风险/依赖**：避免无数据支撑地彻底换风格，先做 A/B 式前后对比。
- **状态**：`[ ]`

### P0-4 把搜索升级为第一主入口

- **问题**：搜索存在，但首屏封面中不可直接使用；进入工具箱后无自动建议。
- **动作**：首屏提供可直接输入的统一搜索；支持名称、能力、描述、标签和域名；输入时显示分类建议、匹配站点和常见意图；支持 `/` 或 `Ctrl/⌘+K` 聚焦；保留清空与键盘导航。
- **预期收益**：有明确目标的用户更快完成任务。
- **验收指标**：首个有效结果显示 <100ms；键盘可完整操作；搜索成功率 ≥55%；零结果率 ≤8%。
- **风险/依赖**：先做本地索引，不引入沉重搜索服务。
- **状态**：`[ ]`

### P0-5 修复搜索零结果体验

- **问题**：零结果时显示“宇宙正在展开/AI Agent维护”，没有解释原因和下一步。
- **动作**：显示搜索词、清除筛选按钮、相近标签、同分类推荐、投稿/反馈入口；区分“数据加载失败”和“搜索无结果”。
- **预期收益**：减少死路，帮助用户恢复探索。
- **验收指标**：零结果页面至少提供 3 个可执行选项；数据接口失败时明确提示并可重试；自动化测试覆盖两种状态。
- **风险/依赖**：建议词需要使用现有标签和名称生成，不调用付费模型。
- **状态**：`[ ]`

### P0-6 清理占位功能与错误入口

- **问题**：禁用的笔记/模板/素材、恐龙游戏和假投稿邮箱降低可信度。
- **动作**：从主导航移除未完成能力；恐龙游戏降级到彩蛋；投稿入口改为真实可用的表单、邮箱或暂时移除。
- **预期收益**：导航更聚焦，访客不会碰到“看起来能用、实际不能用”的功能。
- **验收指标**：主导航中无 disabled 占位项；无 `example.com`；每个可见入口都有实际行为。
- **风险/依赖**：如暂时没有投稿处理流程，宁可先移除。
- **状态**：`[ ]`

### P0-7 建立站点可信度字段

- **问题**：卡片只有描述和标签，用户看不到什么时候收录、何时验证、是否由白刀推荐。
- **动作**：为站点增加 `added_at`、`verified_at`、`status`、`editor_note`、`featured`；先只为精选站点人工补充，历史站点分批迁移。
- **预期收益**：从链接目录升级为可信策展。
- **验收指标**：所有编辑精选都有推荐理由和验证日期；新站新增时字段校验自动执行；过期站点进入待复查状态。
- **风险/依赖**：历史日期不可伪造；未知值必须标“未知”，不能用当前日期冒充。
- **状态**：`[ ]`

### P0-8 修复基础产品与SEO完整性

- **问题**：Manifest 返回 HTML；缺少可验证的结构化策展信息。
- **动作**：修复或移除错误 Manifest；核对 robots、sitemap、canonical、OG 图片；加入合适的 `WebSite` 与 `ItemList` JSON-LD；更新过时的“18+分类”描述。
- **预期收益**：搜索分享展示更可信，避免无效技术信号。
- **验收指标**：Manifest/robots/sitemap MIME 正确；结构化数据验证通过；OG 预览正常；无不存在的路由或资源。
- **风险/依赖**：不要为每个外部站点伪造独立页面或评论评分。
- **状态**：`[ ]`

## 五、P1：形成编辑策展与持续回访理由

> 目标：让访客看到的不只是 217 张卡片，而是“今天为什么值得来”。

### P1-1 增加“本周精选”入口

- **问题**：所有站点平铺，头部大厂长期占据第一屏，新内容不可见。
- **动作**：在列表前加入 3–6 个编辑精选，展示一句“推荐理由”、适用人群、是否免费和验证日期；每周真实轮换。
- **预期收益**：建立编辑人格和发现感。
- **验收指标**：每个精选都有人工理由；精选区外链点击率高于普通卡片；至少每周更新一次。
- **风险/依赖**：不能自动把权重最高等同于编辑精选。
- **状态**：`[ ]`

### P1-2 增加“最近新增/最近验证”

- **问题**：用户不知道网站是否持续更新，也没有回访理由。
- **动作**：基于真实 `added_at/verified_at` 展示最近新增、最近复查和已下架摘要；首页显示更新时间但不伪造日期。
- **预期收益**：证明站点在维护，提高回访和信任。
- **验收指标**：新增站上线后自动进入最近新增；验证日期来源可追溯；7 日回访率连续两轮提升。
- **风险/依赖**：依赖 P0-7 数据字段。
- **状态**：`[ ]`

### P1-3 从“按名称找”升级为“按任务找”

- **问题**：分类以产品形态为主，新手常常不知道该选哪类。
- **动作**：增加任务型快捷入口，如“写一篇文章”“做一张海报”“生成短视频”“研究一个问题”“写代码”“找设计灵感”；每个任务映射到现有能力和筛选组合。
- **预期收益**：降低 AI 产品知识门槛。
- **验收指标**：任务入口到站点点击率 ≥35%；每个任务结果经过人工审查；无空结果任务。
- **风险/依赖**：任务不宜超过 6–8 个，避免又变成一套复杂分类。
- **状态**：`[ ]`

### P1-4 优化卡片信息层级

- **问题**：标签过多且颜色相近，描述截断，底部两个图标按钮语义弱。
- **动作**：首层只保留 2–3 个决策标签；突出“适合什么”和一个限制；外链按钮显示“访问”，收藏按钮保持明确文本或 tooltip；详情中展示完整说明、替代品和上下游关系。
- **预期收益**：更快比较卡片，降低视觉噪音。
- **验收指标**：手机首屏至少完整显示 1.5 张卡；所有按钮有可见或辅助文本；卡片点击误触测试通过。
- **风险/依赖**：不要把详情全部塞回卡片。
- **状态**：`[ ]`

### P1-5 优化移动端分类与筛选

- **问题**：手机分类依赖汉堡侧栏，标签横向挤压，用户容易困在 135 张长列表中。
- **动作**：增加底部或顶部紧凑分类入口；筛选抽屉显示已选条件和结果数；标签区支持“更多/收起”；记住最近分类。
- **预期收益**：单手快速缩小范围。
- **验收指标**：从首页到任意二级分类 ≤2 次操作；无横向页面溢出；44px 触控目标覆盖率 100%。
- **风险/依赖**：不与现有侧栏重复展示全部树结构。
- **状态**：`[ ]`

### P1-6 让随机发现成为有上下文的探索

- **问题**：随机功能醒目，但结果若完全随机，用户不知道为什么值得看。
- **动作**：随机前允许选择“工具/审美/灵感”；结果展示一句推荐理由及“再来一个”；记录随机后是否打开站点。
- **预期收益**：强化网站独特的发现体验。
- **验收指标**：随机发现转化率 ≥25%；同一会话短期不重复；NSFW 内容默认不随机出现。
- **风险/依赖**：需要排除失效和待验证站点。
- **状态**：`[ ]`

### P1-7 强化收藏与最近使用

- **问题**：收藏只显示星形数量，价值表达弱；没有最近打开。
- **动作**：收藏夹显示分类、导出/导入；增加仅本地保存的“最近打开”；首页给回访用户一个小型继续探索区。
- **预期收益**：从一次性导航变成个人工具入口。
- **验收指标**：收藏持久化测试通过；支持清空和导出；收藏率 ≥8%；不强制注册。
- **风险/依赖**：明确数据只保存在浏览器，清理缓存会丢失。
- **状态**：`[ ]`

### P1-8 加入站点反馈闭环

- **问题**：用户遇到失效、收费变化或描述错误时无法直接反馈。
- **动作**：详情页提供“链接失效/信息有误/推荐收录”三种轻量反馈；后台进入待核验队列，不自动改数据。
- **预期收益**：利用真实访客改善内容质量。
- **验收指标**：反馈可追踪、可关闭；不暴露管理API；每周处理一次待核验项。
- **风险/依赖**：需要防垃圾提交和频率限制。
- **状态**：`[ ]`

## 六、P2：建立内容差异化和自然增长

### P2-1 建立“白刀短评”

- **问题**：普通产品描述可以在任何导航站复制，缺少独特判断。
- **动作**：为高价值站点补 30–80 字短评：最佳用途、优点、限制、替代品；优先覆盖点击最高的 30 个站点。
- **预期收益**：形成不可替代的编辑价值和搜索内容。
- **验收指标**：前 30 个站点有人工短评；短评不是官网文案改写；详情点击到外链的转化提升。
- **风险/依赖**：必须人工复核，不批量生成空泛赞美。
- **状态**：`[ ]`

### P2-2 建立可分享的主题集合

- **问题**：当前筛选状态难以成为独立内容资产。
- **动作**：制作主题集合，如“免费AI绘图入门”“中文深度研究工具”“独立开发者工具栈”；拥有稳定 URL、简介、更新日期和分享图。
- **预期收益**：提高分享、搜索收录和回访。
- **验收指标**：首批 6 个集合；每个 5–12 个站点；URL 可分享并恢复筛选状态；分享点击可测量。
- **风险/依赖**：不批量制造薄内容页面。
- **状态**：`[ ]`

### P2-3 提升模型榜的决策价值

- **问题**：模型图表数据丰富，但新用户不一定理解如何选择。
- **动作**：增加“便宜好用/能力最强/最新/开源”快捷视图；解释数据来源、更新时间、价格单位和筛选规则；提供分类内 Top 3 摘要。
- **预期收益**：把模型榜从炫酷图表变成选择工具。
- **验收指标**：首次访问者能在 30 秒内找出一个适合条件的模型；数据来源和更新时间始终可见；图表移动端测试通过。
- **风险/依赖**：不能把不同类别能力分数直接横向比较。
- **状态**：`[ ]`

### P2-4 建立可信维护页

- **问题**：访客看不到收录标准、更新机制和删除规则。
- **动作**：公开“如何收录/如何验证/为何删除/数据来源/隐私”页面；展示最近维护摘要。
- **预期收益**：形成透明度和品牌信任。
- **验收指标**：所有规则可从页脚或个人简介访问；内容与实际流程一致；不披露后台安全细节。
- **风险/依赖**：规则变化后必须同步更新。
- **状态**：`[ ]`

### P2-5 SEO 与分享增长实验

- **问题**：单页首页承载全部内容，长尾搜索和主题分享能力有限。
- **动作**：只为高质量分类、主题集合和模型榜生成可索引页面；完善标题、摘要、ItemList 结构化数据和社交分享卡；提交搜索引擎站长平台。
- **预期收益**：获得可验证的自然真人流量。
- **验收指标**：索引页面均有独特内容；Search Console/Bing Webmaster 能看到展现和点击；无批量薄页。
- **风险/依赖**：先完成内容差异化，再扩页面。
- **状态**：`[ ]`

### P2-6 性能与可访问性持续门禁

- **问题**：当前性能不错，但随着精选区、分析和主题页面增加可能退化。
- **动作**：加入 Lighthouse/Playwright 门禁；检查键盘、焦点、对比度、减少动画、屏幕阅读器语义；给图片固定尺寸并继续按需加载。
- **预期收益**：保持移动端流畅，覆盖更多用户。
- **验收指标**：Lighthouse 性能/可访问性/最佳实践/SEO 均 ≥90；核心路径自动化 100% 通过；无新增控制台错误。
- **风险/依赖**：实验性视觉不得绕过门禁。
- **状态**：`[ ]`

## 七、P3：有数据后再做的长期能力

### P3-1 匿名个性化首页

- **动作**：根据本地最近分类、收藏和点击，调整“继续探索”，不上传个人画像。
- **启动条件**：至少有 500 个可确认真人会话，且 P1 收藏/最近使用已稳定。
- **验收指标**：个性化区点击率显著高于通用区，并提供一键关闭和清空。
- **状态**：`[ ]`

### P3-2 社区推荐与公开策展

- **动作**：允许用户提交主题集合或站点建议，经人工审核后发布；不直接开放评论区。
- **启动条件**：每周稳定收到有效反馈，且有审核能力。
- **验收指标**：垃圾内容可控；所有公开推荐可追溯到审核记录。
- **状态**：`[ ]`

### P3-3 多版本策展实验

- **动作**：对首屏文案、精选布局和任务入口做匿名分流实验。
- **启动条件**：单个实验至少有 200 个可确认真人会话，否则不下结论。
- **验收指标**：预先声明主指标和停止条件；不以偶然波动冒充提升。
- **状态**：`[ ]`
